# 本机项目目录盘点与登记

同一业务项目的前后端、框架、工作副本和归档目录登记到同一项目；工具、研究原型、参考资料应明确标注类别，不能作为业务完成率或验收事实。没有有效 Git 提交和远端的资料目录只登记本地来源，不伪造 GitLab/GitHub 仓库。

原始目录通过独立的只读 bind mount 关联到本机登记目录。项目清单、目录索引和项目认知文件放在忽略的 `.local` 中，不能提交原始材料、凭据或个人目录清单。不要挂载整个用户主目录。

生成的材料目录可以加入内容检索，但其文件名和项目背景不应触发业务事项推断。使用 `analysis.summary_excluded_paths` 指定不参与业务摘要提取的相对文件路径；该选项不关闭检索索引。新发现、尚未验收的项目可关闭 `analysis.enabled`，保留目录检索和背景记录。原有项目的可靠进度证据应保留。

项目数量增多时，人员归属投影不再随每个项目请求重读全部历史。投影根据数据库身份及快照/Agent/远端事件的最大 ID 和数量复用，最长 15 秒，并发请求共用一次重建；绑定/解绑身份强制更新，失败不发布缓存标记。事件录入、删除及数据库切换会触发重新计算，年龄状态最多延迟 15 秒。

验收应包含：全部登记条目可读取背景与索引、关键词检索可命中新增条目、原项目记录保留、项目挂载只读、未调用大模型，以及项目首页的真实响应时间。


项目总览支持按声明的分组 / 团队筛选，以及按项目 ID、负责人、背景检索；不猜测缺失的分类。今日关注按每条事实自己的来源日期判断时效，超过 14 天的事项按项目合并为一次历史核对提醒。未知日期保留为未知；更新其他材料不能让旧问题变新。历史核对的内容变化会重新出现，指纹只在浏览器本地保存，不保存正文。

问题摘要排除空标题和明确“无失败 / 0 failed”的成功记录，但通过数不能掩盖同一记录中的真实失败。任务识别排除章节标题、表头中的编号和功能规格的操作说明；原材料与检索不删除。本周提交按 UTC 周一零点起的自然周统计，排除未来时间，页面明确显示统计时区。

阶段统一保留两种语义：有效认知文件中的记录阶段，以及材料自动推断阶段。简报新增 recorded_stage，兼容中央 v1 的 files.project_intelligence 存储。首页、详情和复制简报优先显示记录阶段并带更新时间；自动推断仍单独保留用于核对，不覆盖原记录。

大目录的文件名元数据应分成小索引页，避免正文索引行数与长度上限隐藏尾部文件。约定 inventory/catalog-NNN.md 的行格式为“文件名 | 来源 项目内相对路径 | 修改日期 YYYY-MM-DD”。检索将登记行展开为真实文件名和来源路径，明确 metadata_only、版本未知，不声称读取正文；保留索引页与行号用于追溯。逐条元数据不增加已读取正文数量。索引仅接受相对路径、无越界项且文件名与路径末尾一致；已有原文件检索结果优先于目录副本。

多项目首页最多并发加载 4 个项目（每项目最多两个来源请求），保留列表顺序；新一轮刷新会停止旧轮次继续排队。失败卡片可仅重试未读来源，保留成功的数据，忽略迟到的旧轮次结果。微信确定性查询同样区分记录阶段、资料推断和目录元数据，资料目录不冒充代码仓库；长简报把资料日期放在摘录之前，避免截断后丢失时效提示。

项目进展逐条保留完成、进行中、问题、下一步和指标的来源路径及资料日期；无法定位时明确标为未知，不用全局更新时间代替某条事实的日期。主摘要支持展开剩余事项。查找来源只在当前项目的材料检索中定位相对路径，不打开主机文件或外部地址；切换项目后的迟到导航忽略。完成标题、进度表头和功能规格模板不作为成果或问题；其余规则摘录仍须结合原文核对。
