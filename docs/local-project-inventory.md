# 本机项目目录盘点与登记

同一业务项目的前后端、框架、工作副本和归档目录登记到同一项目；工具、研究原型、参考资料应明确标注类别，不能作为业务完成率或验收事实。没有有效 Git 提交和远端的资料目录只登记本地来源，不伪造 GitLab/GitHub 仓库。

原始目录通过独立的只读 bind mount 关联到本机登记目录。项目清单、目录索引和项目认知文件放在忽略的 `.local` 中，不能提交原始材料、凭据或个人目录清单。不要挂载整个用户主目录。

生成的材料目录可以加入内容检索，但其文件名和项目背景不应触发业务事项推断。使用 `analysis.summary_excluded_paths` 指定不参与业务摘要提取的相对文件路径；该选项不关闭检索索引。新发现、尚未验收的项目可关闭 `analysis.enabled`，保留目录检索和背景记录。原有项目的可靠进度证据应保留。

项目数量增多时，人员归属投影不再随每个项目请求重读全部历史。投影根据数据库身份及快照/Agent/远端事件的最大 ID 和数量复用，最长 15 秒，并发请求共用一次重建；绑定/解绑身份强制更新，失败不发布缓存标记。事件录入、删除及数据库切换会触发重新计算，年龄状态最多延迟 15 秒。

验收应包含：全部登记条目可读取背景与索引、关键词检索可命中新增条目、原项目记录保留、项目挂载只读、未调用大模型，以及项目首页的真实响应时间。
