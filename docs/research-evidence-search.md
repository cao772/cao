# 无需模型的证据检索优化

日期：2026-10-03。

## 参考与取舍

- [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)：检索片段保留背景上下文。当前系统使用已有项目、来源、日期与正文定位信息，不使用模型生成上下文，也未实现该文的向量检索或完整 Contextual BM25。
- [Robertson & Zaragoza, BM25 and Beyond](https://doi.org/10.1561/1500000019)：利用词频饱和与长度归一化排序。当前使用 BM25 对已召回的候选片段排序；英文技术标识保留，中文采用双字切分。
- [An Analysis of Fusion Functions for Hybrid Retrieval](https://arxiv.org/abs/2210.11934)：融合策略具有参数与数据依赖。当前采用等权 RRF（k=60）融合既有字段排序与 BM25 候选排序，以固定测试验证，而非假设论文结论可直接迁移。本实现两个通道都是词法检索，不包含语义向量检索。
- [BEIR](https://arxiv.org/abs/2104.08663)：以不同任务上的实际检索评价选方法。当前保留原查询来源集合，并测试中文、编号、长文、SQL特殊字符、项目范围隔离与材料来源缺失的情况。固定用例和本机抽查不等价于 BEIR 全量评测，不报告召回率提升百分比。
- [Linear Inbox](https://linear.app/docs/inbox)：收件箱允许处理、延期、重新关注。系统已有今日关注跟进状态；状态只是个人处理提醒，不替代项目事实的确认。

## 已实现

1. 对授权的材料/聊天候选做字段排序与 BM25 排名融合；保留已有命中，不增加模型调用或依赖。
2. 片段围绕实际关键词出现处截取，保留原文字形和上下文；长消息后段的命中也可见。
3. 跨项目结果显示命中字段、材料位置（有定位信息时）、原始来源时间和采集时间；关键词高亮先转义，避免来源内容注入页面。
4. `%`、`_`、反斜线作为聊天查询的字面量；查询持续限制在指定项目。
5. 材料快照缺失时，授权聊天仍能返回，同时明确缺失来源。
6. 浏览器行为回归测试进入 CI。

## 验证与限制

Python 服务回归 178 项通过；之后补充材料缺失而聊天可用的用例，与 portfolio_search 的其余用例共同 5 项通过。浏览器逻辑 11 项通过。3 条既有弃用警告保留。

本机抽查“框架”“8192”“验收”“%”“env_file”：单次响应约 0.24–0.44 秒；“框架”更新前的 3 条来源全部保留，“8192”返回授权群聊，并可见命中正文。时间是本机抽查，不是吞吐量基准或性能提升比例。

候选每项目各来源最多 100 条；排序只能优化已经召回的候选，不能恢复未采集或未被原检索召回的资料。中文双字切分属于轻量词法方案，不具备语义理解。完整评测集、全量索引与模型增强需后续按真实检索失败案例决定。
